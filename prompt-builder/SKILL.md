# 요청문 빌더 (Prompt Builder)

거친 요청을 **복사해 바로 쓰는 프롬프트**로 다듬는 스킬.

## 언제 쓰나
- 사용자가 AI(GPT·Claude 등)에 무언가 시키려는데 어떻게 물을지 막연할 때
- "이 요청 다듬어줘 / 프롬프트로 만들어줘 / 더 잘 물어보게 해줘" 같은 요청
- 문서·영수증·오류화면 분석, 자료 조사, 코딩 질문, 이미지 분석·생성·편집을 맡기기 직전

## 밑에 깔린 원칙 (왜 이렇게 다듬는가)
1. **골라 넣기**: 컨텍스트는 한정된 예산이다. 목표에 필요한 것만 넣는다 — 많이 넣기 ≠ 좋은 답.
2. **출력 공간 남기기**: 입력·출력·추론이 한 예산을 나눠 쓴다. 긴 답이 필요하면 형식·분량을 먼저 정한다.
3. **불확실성 표시**: 자료에 없는 것은 추정하지 말고 "확인 불가"로 표시하게 한다.
4. **한국어 주의**: 한국어는 영어보다 토큰을 약 2배 쓴다 → "관련 부분만 넣기"가 더 중요하다.

## 진행 방법
1. 사용자의 거친 요청에서 **작업 종류**를 먼저 판별한다.
   - 텍스트 작업(분석·추출·조사·작성·코딩) → **경로 A (GCROUND)**
   - 이미지 **분석**(읽기·추출) → **경로 B**
   - 이미지 **생성/편집**(그리기·다시그리기) → **경로 C** (Claude는 이미지 생성 불가 → 전용 모델 필요함을 알린다)
2. 이미 주어진 정보로 칸을 채우고, **빠진 핵심 1~2개만** 되묻는다. 심문하듯 전부 묻지 말 것 — 나머지는 합리적 기본값으로 채우고 "(가정)"으로 표시한다.
3. 최종 프롬프트를 **코드블록**으로 출력한다 (복사용).
4. 작업에 맞는 **검수 주의 1~2줄**을 덧붙인다.

## 경로 A — 텍스트 작업 (GCROUND)

```text
[목표] 내가 얻고 싶은 결과는 무엇인가 (한 가지로)
[배경] 반드시 알아야 할 사실만
[자료] 이번 판단에 쓸 자료만 붙인다
[조건] 지켜야 할 기준과 하지 말아야 할 일
[출력] 형식, 길이, 대상 독자
[불확실성] 근거가 없으면 추정 말고 표시
[다음 단계] 추가 자료가 필요하면 무엇인지 먼저 물어 달라
```
검수 주의: 수치·날짜·고유명사는 원본과 대조. 목표가 여러 개면 요청을 쪼갠다.

## 경로 B — 이미지 분석 (읽기)

```text
[목표] 이 이미지에서 무엇을 얻을 것인가
[범위] 어느 영역만 볼 것인가
[출력] 표 / JSON / 체크리스트 중 무엇인가
[근거] 읽은 원문과 위치를 함께 적게 한다
[불확실성] 읽히지 않으면 추측 말고 '판독 어려움'으로 표시
```
검수 주의: 작은 글자는 그 영역만 잘라 확대해 다시 넣는다. **한글·금액·수치는 반드시 원본과 대조** (AI 비전은 비라틴 문자·정확한 개수에 약함).

## 경로 C — 이미지 생성/편집

**생성(텍스트→이미지)** — 시안 탐색용:
```text
용도 + 대상 + 상황 + 구도 + 스타일/분위기 + 색상 + 화면비 + 포함할 것/제외할 것
```
**편집(이미지→이미지)** — '유지할 것'을 반드시 먼저:
```text
[반드시 유지] 형태·로고 위치·각도·그림자 등 보존할 것
[바꿀 것] 한 번에 한두 가지만
[바꾸지 말 것] 색상·비율·글자·추가 소품
[출력] 크기·화면비·여백
```
검수 주의: 이미지 속 글자·로고는 변형되기 쉬우니 **최종 문구는 편집 도구에서 직접** 넣는다. **Claude는 이미지를 만들지 못한다** → GPT Image·DALL·E 등 생성 모델을 쓴다.

## 마무리
프롬프트를 낸 뒤, 사용자가 실제로 쓸 AI(GPT/Claude 등)에 붙여넣으면 된다고 안내한다. 결과가 나오면 위 검수 주의로 확인하도록 권한다. 예시 변환은 `references/examples.md` 참고.
