# 요청문 빌더 — Prompt Builder Skill

짧고 모호한 요청에서 목표·자료·출력 형식·불확실성 처리 기준을 확인해 실행 가능한 프롬프트로 정리하는 Claude Code용 스킬입니다.

작업 종류에 따라 필요한 정보와 검수 기준만 보충하도록 설계했습니다. 결과에 영향을 주는 핵심 정보가 빠졌을 때 1~2개를 질문하고, 나머지 기본값은 가정으로 표시합니다.

> 사용자는 원하는 결과를 정하고, 스킬은 그 의도를 AI가 수행하고 사용자가 검수할 수 있는 요청으로 정리합니다.

이 스킬은 요청문을 작성하며, 문서 분석·코딩·이미지 작업 자체를 실행하지 않습니다.

## 요청이 어떻게 바뀌는가

저장소에 포함된 영수증 분석 예시입니다. 실제 모델 실행 결과나 성능 평가 자료는 아닙니다.

**입력**

> 이 영수증 정리해줘.

**다듬은 프롬프트**

```text
이 이미지에서 거래일시, 상호, 공급가액, 세액, 합계만 추출해 표로 정리해 줘.
각 값 옆에 이미지에서 읽은 원문을 함께 적어 줘.
글자가 불명확하면 추측하지 말고 '판독 어려움'이라고 표시해 줘.
```

**함께 제공하는 검수 안내**

> 한글 상호·금액은 원본과 대조하세요. 작은 글자는 해당 부분을 확대해 다시 제공하세요.

막연한 “정리”를 **추출 항목·출력 형식·근거·판독 실패 처리**로 구체화합니다. 다른 작업의 변환 예시는 [예시 모음](prompt-builder/references/examples.md)에 있습니다.

## 지원 작업과 보충 정보

아래는 작업별 설계를 설명하는 예시입니다.

| 작업 | 거친 요청 | 보충할 핵심 정보 |
|---|---|---|
| 영수증 분석 | 이 영수증 정리해줘 | 추출 항목, 원문 근거, 판독 실패 처리 |
| 이미지 편집 | 배경을 깔끔하게 바꿔줘 | 바꿀 배경, 유지할 대상, 바꾸지 말아야 할 요소 |
| 코딩 | 이 오류 고쳐줘 | 실행환경, 오류와 재현 방법, 기대 동작, 변경 범위 |

이미 알려진 정보는 다시 묻지 않고 요청문에 반영합니다. 표의 항목을 매번 전부 질문하는 방식은 아닙니다.

## 프로젝트 배경

문서 분석, 자료 조사, 코딩 질문, 이미지 편집을 AI에 맡길 때는 원하는 결과뿐 아니라 사용할 자료와 지켜야 할 조건도 전달해야 합니다. 짧은 요청만으로는 무엇을 확인하고 어떤 형태로 답해야 하는지가 모호해질 수 있습니다.

이 프로젝트는 사용자가 매번 요청의 구성 요소를 직접 떠올려 작성해야 하는 부담을 줄이려는 도구입니다. 모든 작업에 긴 양식을 적용하기보다, 작업에 맞는 틀을 고르고 필요한 정보만 채우도록 설계했습니다.

## 작동 흐름

1. **작업 분류:** 텍스트 작업, 이미지 분석, 이미지 생성·편집으로 나눕니다.
2. **핵심 확인:** 이미 주어진 정보를 활용하고, 빠진 핵심 정보 1~2개만 질문합니다. 나머지 기본값은 가정임을 표시합니다.
3. **요청문 작성:** 복사해서 사용할 수 있도록 최종 프롬프트를 코드블록으로 제공합니다.
4. **사용자 검토:** 검수 주의 1~2줄을 함께 제공합니다. 사용자는 의도와 가정을 확인한 뒤 사용할 AI에 전달하고, 결과를 원본과 대조합니다.

## 작업마다 다른 틀을 쓰는 이유

| 작업 | 정리하는 내용 | 설계 의도 |
|---|---|---|
| 텍스트 분석·추출·조사·작성·코딩 | 목표·배경·자료·조건·출력·불확실성·다음 단계 | 작업 범위와 결과 형식을 명확히 함 |
| 이미지 분석 | 목표·범위·출력·근거·불확실성 | 읽은 내용과 추측을 구분하고 원본 대조를 도움 |
| 이미지 생성·편집 | 생성 시 용도·구도·스타일, 편집 시 유지할 것·바꿀 것·바꾸지 말 것 | 원하는 변경과 보존할 요소를 구분함 |

예를 들어 이미지 편집은 멋진 결과를 설명하는 것만큼 **무엇을 그대로 유지할지**가 중요합니다. 반면 영수증 분석에서는 읽은 원문과 판독이 어려운 부분을 표시하는 것이 중요합니다. 이런 차이를 세 경로로 나눴습니다.

## AI와 사용자의 역할

| 구성 | 역할 |
|---|---|
| Prompt Builder Skill | 작업 분류, 필수정보 확인, 요청문 구조와 검수 안내를 정의 |
| Claude | 사용자 의도를 해석하고 스킬 지침에 따라 질문·요청문 작성 |
| 사용자 | 목표와 자료를 제공하고 가정·최종 요청문·실제 결과 검수 |

이 저장소는 지침과 예시로 구성되며 별도의 실행 프로그램이나 출력 검증기는 없습니다. 실제 응답이 지침을 따랐는지는 사용 사례 또는 평가 세트에서 확인해야 합니다.

## 현재 검증 범위

현재 저장소에는 텍스트·이미지 분석·이미지 생성의 **설명용 변환 예시 3개**가 있습니다. 이는 설계를 보여주는 문서이며, 모델 실행 로그나 지침 준수 평가 결과는 아닙니다. 답변 정확도·재질문 횟수·작업 시간의 개선 효과는 아직 측정하지 않았습니다.

## 한계와 다음 평가

- 모델이 스킬 지침을 항상 그대로 따르는 것은 아닙니다.
- 잘 정리된 프롬프트도 실제 답변의 사실 정확성을 보장하지는 않습니다.
- 질문 수와 프롬프트 길이가 모든 작업에서 적절한지는 아직 평가하지 않았습니다.

다음 단계는 세 경로별 3개씩 **총 9개 요청을 수작업으로 검토**하는 것입니다. 아래는 수행 예정인 평가 기준입니다.

| 평가 항목 | 확인할 내용 |
|---|---|
| 목표 보존 | 사용자가 원한 결과를 바꾸지 않았는가 |
| 필수정보 보충 | 실행에 필요한 핵심 조건을 반영했는가 |
| 불필요한 가정 | 임의로 추가한 요구가 있는가, 가정을 표시했는가 |
| 질문 절제 | 질문을 핵심 1~2개로 제한하고 이미 있는 정보를 다시 묻지 않았는가 |
| 검수 가능성 | 결과를 무엇과 대조할지 안내했는가 |
| 길이 적절성 | 간단한 요청을 불필요하게 장문화하지 않았는가 |

입력·질문과 답변·최종 프롬프트를 함께 남기고, 지침을 벗어난 사례와 수정 전후를 기록할 계획입니다. 이 평가는 우선 **지침 준수 여부**를 확인하며, 실제 작업 결과의 품질 개선은 별도 비교가 필요합니다.

## 설치와 사용

Claude Code에서 사용할 경우 저장소의 `prompt-builder/` 폴더를 스킬 디렉터리에 복사합니다.

```bash
git clone https://github.com/0gnm0-afk/ai-prompt-builder.git

# 프로젝트에서 사용
mkdir -p .claude/skills
cp -r ai-prompt-builder/prompt-builder .claude/skills/

# 또는 사용자 전역에서 사용
mkdir -p ~/.claude/skills
cp -r ai-prompt-builder/prompt-builder ~/.claude/skills/
```

위 명령은 Bash 기준입니다. Windows에서는 같은 위치로 폴더를 직접 복사할 수 있습니다.

설치 후 다음처럼 요청합니다.

> 이 영수증에서 필요한 항목을 추출하고 싶은데, AI에 넣을 프롬프트로 다듬어줘.

생성된 요청문은 사용할 AI에 복사해 전달합니다. 이미지 생성·편집 요청문은 해당 기능을 지원하는 도구에서 사용합니다.
